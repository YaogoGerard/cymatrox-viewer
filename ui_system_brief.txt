# CYMATROX VIEWER — SYSTEM EXPLANATION FOR AI INTERFACE DESIGN

## Core identity
Cymatrox Viewer is a real-time, interactive cymatics laboratory. It renders physics computed by a separate GPU-accelerated simulation library (cymatrox) inside a Bevy 3D/2D viewport with an egui control panel on the left. The system is a headless physics engine (pure computation, outputs positions/heights/pressures) consumed live by a renderer — not a toy visualization but a viewer of a validated physics solver.

## Three simulation domains

1. GRANULAR (Chladni plates) — Solid domain. 4096 grains on an idealized vibrating plate. Visualization: 2D top-down, instanced grains, velocity-magnitude color. Physics: Sophie Germain plate + Newtonian particle kinetics. Driving: frequency (Hz), amplitude (normalized) mapped to plate displacement 1e-3 m. Parameters: drag, restitution, coupling stiffness k (N/m).

2. FLUID (Faraday waves) — Liquid surface on circular dish. Visualization: 3D heightmap deformed in Y with lighting, circular rim/dish. Time-smoothed + light spatial smoothing. Physics: damped wave + Mathieu (Faraday) parametric forcing + Laplace–Young surface tension. Driving: vertical acceleration 10 m/s² scale. Parameters: density, surface tension, depth, damping. Runs at high fixed physics step rate for instability growth.

3. ACOUSTIC (standing pressure/acoustic levitation) — Gas domain. Visualization: sparse voxel volume (render only where |pressure| > cutoff), translucent chamber, two opposing transducers with glow, levitating particle. Physics: Helmholtz + Gor'kov potential. Driving: transducer normal velocity 2e-3 m/s scale (ultrasonic typical). Few parameters exposed.

## Architecture & data flow
- Three threads: Bevy main (UI+render, ECS), sim thread ("cymatrox-master", owns cymatrox::GpuContext wgpu device, independent from Bevy), audio thread (CPAL+realfft mic capture).
- Unidirectional: egui UI -> SimParams (latest-wins slot, coalesced, never blocks) -> sim thread sanitizes/clamps -> hot-updates (freq/amplitude) immediately; solver/liquid changes debounced 300ms while stable -> rebuild simulation on debounce expiry. 
- Frame-rate independent pacing: accumulator advances fixed steps/sec per module (granular/acoustic ~60, fluid ~4800 equivalent) using solver dt; capped backlog prevents catch-up spiral.
- State: SimState holds latest frames + status string + error boolean. ActiveModule enum selects view + context controls. Module defaults applied once per first visit.
- Viewport: left egui panel (responsive width). 3D modules use orbit camera with panel-offset viewport; granular 2D. Render layers toggle visibility per module.

## UI purpose & constraints
Purpose: precise scientific control + clear system state, without obscuring the 3D/2D phenomenon. Must be readable in dark, minimal friction when tuning physics.

Constraints to preserve exactly:
- All parameter ranges/units and mapping scales unchanged (log freq 20–20000, amplitude units per module as above).
- Latest-wins, debounce 300ms, fixed steps/sec pacing, hot-update semantics.
- Panel width affects camera viewport (must remain functional).
- Voice control mapping (mic RMS+dominant freq) unchanged.
- Error visibility + streaming/starting states unchanged.
- Implementable in egui (Bevy+egui). No GUI stack change.

## Design intent
Aim for modern instrument UI: dark technical aesthetic with subtle depth, segmented module tabs, card groups, inline value+unit on sliders, clear status pill. Prioritize functional clarity, coherence across modules, minimal nesting. Preserve scientific legibility while looking contemporary.
